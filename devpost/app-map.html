Weppy: source map

Public sales assistant with two transports. Entry: src/worker.ts; shared conversation engine: src/chat.ts; persistent storage: Cloudflare D1; browser client: public/.

One report, one private owner

Telegram webhook
handleWebhook verifies secret; handleUpdate claims update ID and accepts only private chats.
Web API
/api/session, /api/message, /api/voice, /api/export map a localStorage token to owner web:<token>.
Shared engine
src/chat.ts owns onboarding, extraction, clarification, recap, follow-ups, settings and CSV for both transports.
Personal profile
loadProfile/saveProfile; D1 profiles.owner_id is the chat ID or web owner.
AI report
transcribeAudio, extractReport; credentials are Worker secrets, never sent to the client.
Pipeline
loadNotes/saveNote; D1 composite key (owner_id, id).
Private actions
Recap, follow-ups, CSV and view_<id> detail always scope to the owner.
Scheduled messages
runCron selects due schedules, skips web:% owners, and queries notes only after owner selection.

Reusable contracts

  • Tenant scope: resource IDs alone are not authorization; private reads include owner ID.
  • Transport parity: both clients call the same engine, so behavior cannot drift between web and Telegram.
  • Webhook admission: reject unmatched provider secret before update processing.
  • Idempotency: D1 claims incoming update IDs to avoid replaying provider retries.
  • Quota honesty: a free service is best effort, not an uptime promise.
Owner step remaining: set the real Telegram/Groq secrets and register Telegram setWebhook to enable live bot delivery. Web delivery is live at the Worker URL; no owner credentials are stored here.
