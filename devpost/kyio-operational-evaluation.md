# Evaluasi operasional KyioAPI untuk Weppy

**Tanggal penilaian:** 15 Oktober 2026. **Cakupan:** kecocokan operasional sebagai pengganti Groq untuk bot Telegram publik multi-user di Cloudflare Workers; bukan penilaian kualitas model. Tidak ada kode, konfigurasi, deployment, atau data pengguna yang diubah. Tidak ada pengujian generasi API yang dilakukan dalam slice ini.

## Keputusan singkat

**Jangan cutover untuk produksi publik saat ini.** Kyio mengiklankan endpoint OpenAI-compatible dan model `claude-haiku-4-5`, tetapi akun/key yang dibutuhkan untuk akses premium tidak tersedia dalam bukti ini; daftar model bukan verifikasi bahwa permintaan generasi berfungsi atau bahwa model yang disajikan benar-benar terikat pada identitas/versi tertentu. Policy melarang reselling, leasing, atau proxying akses key pada Donation Plan, tetapi tidak menjelaskan apakah backend aplikasi multi-user yang tidak menjual atau mendistribusikan akses Kyio termasuk cakupan larangan; pola ini perlu dikonfirmasi, bukan otomatis dianggap pelanggaran. Batas kuota harian bertentangan antarhalaman, retensi konten prompt/hasil dan penyedia AI hulu tidak dijelaskan, dan tidak ada SLA kontraktual yang ditemukan.

Starter dengan API key adalah jalur teknis yang lebih masuk akal daripada whitelist IP untuk Worker, tetapi **bukan izin penggunaan**: dapatkan persetujuan tertulis Kyio untuk pola integrasi multi-user ini dan klarifikasi kuota, data, model, dan dukungan sebelum mengizinkan perubahan konfigurasi/cutover. Angka harga/limit di bawah adalah pernyataan situs provider, bukan hasil pengukuran.

## Whitelist IP dan Cloudflare Workers

Dokumentasi resmi Cloudflare [Workers TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/) menyatakan khusus koneksi TCP outbound melalui API `connect()` bersumber dari prefix yang bukan bagian dari daftar IP Cloudflare yang dipublikasikan. Ini bukan dokumentasi jalur HTTP `fetch()` yang dipakai integrasi API, sehingga tidak membuktikan alamat sumber `fetch()` Weppy atau kestabilannya. Halaman resmi [Known issues](https://developers.cloudflare.com/workers/platform/known-issues/) menjelaskan batasan subrequest `fetch()` (URL, bukan alamat IP langsung), tetapi sumber yang ditinjau tidak menetapkan IP egress tetap per Worker. Karena itu, **tidak ada bukti di sini bahwa Worker dapat memenuhi whitelist IP Kyio secara stabil**; jangan mengasumsikan alamat dari satu permintaan akan tetap berlaku atau menyebut kestabilan egress telah diuji.

Cloudflare mendokumentasikan [Dedicated egress IPs untuk Gateway](https://developers.cloudflare.com/cloudflare-one/traffic-controls/egress-policies/dedicated-egress-ips/) sebagai add-on Zero Trust Enterprise, dikonfigurasi pada Gateway untuk traffic yang diproksi oleh Gateway. Itu bukan bukti Worker Weppy menggunakan jalur tersebut dan tidak membuktikan keterpakaian untuk Worker `fetch()`. Jangan memilih lifetime whitelist tanpa bukti routing yang benar-benar berlaku untuk Worker ini dan konfirmasi Kyio; Starter berbasis key adalah jalur yang lebih masuk akal untuk dievaluasi, bukan jaminan akses.

## Gate konkret sebelum cutover

Cutover belum diotorisasi kecuali seluruh kondisi berikut dipenuhi, dievaluasi, dan dicatat oleh pemilik layanan:

1. **Izin penggunaan dan paket:** dapatkan jawaban tertulis Kyio yang menyebut eksplisit bot Telegram publik multi-user sebagai integrasi backend aplikasi, penggunaan satu key oleh Worker, apakah ini termasuk proxying pihak ketiga, dan paket yang secara kontraktual mengizinkannya. Pastikan harga, pembaruan manual/berulang, terminasi, dan hak penangguhan untuk use case itu.
2. **Kapasitas yang konsisten:** minta satu tabel kontraktual untuk endpoint/model terpilih: RPM per key dan IP, burst, RPD, kuota bulanan, reset zona waktu, perilaku 429/kuota habis, serta cara memulihkan key/akses setelah blok. Batas yang dijamin harus cukup untuk volume agregat multi-user yang diperkirakan dengan headroom; klaim pemasaran saja tidak lulus.
3. **Privasi/kontrak data:** dapatkan jawaban retensi khusus prompt/output/transkripsi, log payload dan backup, tujuan pemrosesan/pelatihan, daftar upstream/subprosesor dan wilayah AI, kontrol penghapusan, enkripsi/akses, retensi saat terminasi, serta kanal/waktu respons insiden. Lakukan review privasi pada data laporan customer sebelum mengirim konten apa pun.
4. **Model/API yang dapat dipertanggungjawabkan:** konfirmasi model provider/upstream, identitas dan versi, kebijakan alias/fallback, jadwal perubahan/depresiasi, serta dukungan aktual untuk `response_format: {type: "json_object"}`, `temperature`, `max_tokens`, dan kontrak respons yang dibutuhkan. ID `/v1/models` saja bukan bukti. Jalankan benchmark beban kerja nyata secara terkontrol hanya setelah key dan otorisasi tersedia; bandingkan validitas ekstraksi, schema/JSON, latensi/error, dan perilaku batas terhadap Groq tanpa data customer.
5. **Ketersediaan dan kegagalan:** dokumen Kyio yang ditinjau hanya mendukung karakterisasi best-effort/no SLA kontraktual. Pemilik layanan harus secara eksplisit menerima risiko itu atau meminta komitmen tertulis sebelum memutuskan. Jika tidak ada SLA, tetapkan toleransi produk terhadap outage, kuota dan perubahan model; angka “99,9%” tanpa komitmen dan remedy bukan jaminan.
6. **Uji operasi terotorisasi dan aman:** setelah izin/key, validasi satu integrasi minimum dan batas yang disetujui, cek autentikasi, JSON, penggunaan parameter, status dan rate-limit headers, limit quota, penolakan, dan perilaku outage menggunakan prompt sintetis. Tidak menggunakan data pengguna nyata, tidak melakukan stress test, dan tetap dalam limit provider. Simpan hasil sebagai bukti terukur, bukan proyeksi dari klaim.
7. **Whitelisting (hanya jika tetap dipilih):** jangan deploy berdasarkan whitelist sampai ada bukti tertulis Cloudflare bahwa jalur egress statis tersedia dan terikat pada deployment Worker aktual, prosedur failover/IPv4/IPv6 diketahui, dan Kyio mengonfirmasi semua alamat tersebut dapat didaftarkan serta tetap berlaku. Jangan melakukan rotasi IP atau manipulasi header untuk mengakali kontrol.

## Batas bukti dan catatan akuisisi

Halaman primer yang ditinjau: [pricing](https://api.kyio.web.id/pricing), [panduan API key](https://api.kyio.web.id/docs/api-keys), [API usage policy](https://api.kyio.web.id/api-policy), [privacy](https://api.kyio.web.id/privacy), [terms](https://api.kyio.web.id/terms), [disclaimer](https://api.kyio.web.id/disclaimer), dan [homepage](https://api.kyio.web.id/). `/docs` dilaporkan mengembalikan Cloudflare 403; tidak ada upaya bypass. Isi halaman tertentu berhasil dibaca melalui Jina sebagai fallback pembaca, sementara beberapa halaman juga memberi kerangka HTML dari origin; teks provider di atas dikutip dengan menautkan URL Kyio asli. Halaman hukum/policy bersifat pernyataan provider, bukan validasi independen atau kontrak yang ditandatangani.

**Penyimpangan batas pengambilan sumber:** akuisisi Kyio pada slice ini secara tidak sengaja berjumlah 13 fetch ke origin/fallback Kyio, melampaui batas maksimum 9 yang diberikan; sebagian juga tidak berjarak 25 detik. Ini kegagalan prosedural saya, bukan permintaan atau aktivitas parent. Saya menghentikan seluruh fetch Kyio tambahan dan tidak mengulang request. Sumber yang sudah diperoleh cukup untuk evaluasi dokumen, tetapi batas ini tidak dipatuhi; catatan ini disertakan agar parent dapat mempertimbangkannya.

**Tidak tersedia:** key berbayar Kyio untuk menguji generasi, kuota aktual atau kestabilan endpoint; jawaban tertulis atas izin integrasi, kontrak/SLA, retensi konten, dan identitas upstream; serta jaminan Cloudflare egress IP yang terikat pada Worker ini. Penilaian benchmark provider oleh parent harus tetap dipisahkan dari klaim hukum, privasi, dan keandalan di sini.
