Weppy public Telegram Worker

TypeScript Worker · D1 storage · Telegram webhook · Groq extraction/transcription · Asia/Jakarta Cron

Request path

1. Telegram ingress
Validate X-Telegram-Bot-Api-Secret-Token; reject groups/non-private chats.
2. D1 identity and replay check
Claim update ID; resolve private profile by chat_id.
3. AI report
Text or Groq-transcribed voice → strict JSON fields; missing facts stay empty.
4. Owner-only persistence
Store notes under composite (owner_id, id).
5. Chat actions
Clarify/Skip, recap, follow-up, detail and CSV use same owner.
6. Scheduled delivery
Cron claims daily marker atomically before sending to that owner.

D1 ownership model

profiles(owner_id PRIMARY KEY, profile_json, schedule fields)
notes(owner_id, id, created_at, note_json, PRIMARY KEY(owner_id, id))
processed_updates(update_id PRIMARY KEY, created_at)

Note lookup checks both owner and ID. No shared records, group chat, or public read endpoint.

Verification and local operation

npm install
npx wrangler d1 create weppy-public-bot
# update the local binding ID in wrangler.jsonc
npx wrangler d1 execute weppy-public-bot --local --file schema.sql
npm run dev -- --local
node scripts/smoke-worker.mjs
npm run test
npm run typecheck
npx wrangler deploy --dry-run

Tests cover wrong secret, owner-separated profiles/notes, foreign note callbacks, and concurrent Cron delivery claims. Local health/auth smoke is verified; live Telegram/Groq delivery and public deployment still require owner account setup.

Constraints

Free-tier availability is best effort, not guaranteed 24/7; quotas/outages may halt processing. The service has no managed backup/SLA. Avoid customer-sensitive data on the free demo.
